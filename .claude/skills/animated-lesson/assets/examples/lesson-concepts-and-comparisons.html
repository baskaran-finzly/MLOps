The question that separates them

Who decides the next step?

This is the most useful question in the lesson. In a workflow, people decided every step in advance, in code. In an agent, the model decides each next step while it works. Give both the same failing test and watch.

    Anthropic's advice is to find the simplest solution that works, and add complexity only when needed. Use a workflow when you can write the steps down. Use an agent when you can't. And when you use an agent, give it a harness, because its freedom is also where its mistakes come from.

    A surprise

    In a chat window, you are the harness

    Before agents, people coded with AI by chatting: ask for code, paste it into the IDE, run the tests, paste the errors back. In that loop, you are the tool runner, the validator and the safety check. An agent harness does the same jobs for you.

    Same model, same task. The difference is who does the jobs around it. That's why the harness, not the prompt, is what lets an agent work while you're not watching.

    The big question of Level 0

    Why isn't a good prompt enough?

    Here is a "perfect" prompt for the ACH task. Every line on the left is a good instruction. But a prompt can only ask. On the right is what actually makes each one happen.

    The prompt says"Run the tests before you finish."
    →
    Hard · Stop hookThe harness runs ./mvnw verify and won't let the agent stop while it fails.
    The prompt says"Never push to main."
    →
    Hard · Permission ruleBash(git push *) in the deny list. The command never runs.
    The prompt says"Don't touch the ledger code."
    →
    Hard · PreToolUse hookThe guard script cancels any edit under ledger/.
    The prompt says"Follow our architecture."
    →
    Context + checkCLAUDE.md tells it the architecture every session. An architecture test would enforce it.
    The prompt says"Make sure it's correct."
    →
    FeedbackCompiler, unit tests, integration tests and review. Correctness is measured, not promised.
    The prompt says"Remember this for next time."
    →
    MemoryThe model forgets when the session ends. A file like CLAUDE.md doesn't.
    The prompt says"If you're unsure, ask me."
    →
    Human approvalPermission prompts and "ask" rules stop the agent and wait for your answer.
    It can't see resultsA prompt is sent before the work starts. It never sees the test output.
    It can't enforceInstructions are soft. The model usually follows them, not always.
    It can't rememberNext session, it's gone. Each teammate writes it differently.
    It can't check itself"Be careful" doesn't make anything correct. A test does.

    In one sentence

    A prompt asks, a model thinks, a tool acts, an agent loops and decides its own next step, a workflow follows steps people fixed in advance, and the harness is everything around them that runs the loop and keeps it safe and checked.
